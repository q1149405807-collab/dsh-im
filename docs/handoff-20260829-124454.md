# Handoff: dsh-im 飞书双功能开发与排障（2026-08-28/29）

## Current state

### 背景
用户为 dsh-im 飞书机器人（@xmanrui/dsh-im v3.0.6，已连飞书）开发两个功能：
1. **功能1（绑定会话流式推送）**：电脑端在绑定到飞书的会话上发起追问时，飞书端看到流式卡片和最终结果（仅电脑端发起的 turn 推送，非 `im-` rpcId 判别）
2. **功能2（未绑定完成通知）**：电脑端发起的未绑定会话完成时，向 bot owner 私聊推送"已完成"通知

### 已完成的成果

**① 功能代码已实现并部署**（安装目录 lib 为修复版 8044439 字节，含 boundStreams/ownerNotices/keysBoundTo）
- `src/channels/feishu/bridge.mjs`：新增 `#mirrorBoundSessionTurn`（流式镜像）、`#openBoundStream`、`#finalizeBoundSessionTurn`、`#notifyUnboundCompletion`、`#isComputerInitiatedUserMessage`（rpcId 非 `im-` 前缀判定电脑端）、`#sendToOwner`（open_id 私聊推送）；`#onHarnessEvent` 从仅处理 `turn/end` 扩展为处理全部事件
- `src/channels/feishu/feishu-runtime.mjs`：`createBridgeStatus` 加 boundStreams/ownerNotices 字段；bridge 构造传入 ownerOpenIds
- `src/channels/feishu/state-store.mjs`：新增 `keysBoundTo(sessionId)` / `keysWithSession()` 逆映射
- **修复了 `nonEmptyText` / `assistantMessageText` 未定义 bug**（原引用 harness-client.mjs 私有函数，已在 bridge.mjs 补本地定义）

**② 构建环境问题根因已查明并解决**
- 用 **pnpm** 安装依赖构建的 lib（8055078）→ 飞书 0/1 连不上（esbuild 平台/依赖树差异）
- 用 **npm** 安装依赖构建的 lib（8044439）→ 飞书 1/1 正常连接 ✅
- **关键教训：此插件必须用 npm 依赖树构建，不能用 pnpm**

**③ 功能实测**
- 功能2 **已实测成功**：用户收到"✅ 电脑端的任务已完成"通知（session-21480852...45215 是自动化任务，非用户手动创建的）
- 功能1 **代码已触发但未完整验证**：日志显示 bound-session stream 曾因 nonEmptyText bug 失败，修复版已部署待重新测试

**④ 会话列表刷新补丁（解决"飞书会话电脑端看不到"）**
- 根因：Host 广播 `host/session-added` 后 GUI 会话列表未自动刷新；官方 client-runtime 有 `sessions.refresh()` 方法但无定时调用
- 方案：已生成压缩版 asar 补丁（每 30s 调 `sessions.refresh()`），**已写入 `app.asar`**（原版备份在 `app.asar.bak-sessionpoll`）
- ⚠️ **补丁待验证**：写入后 DSH 已重启（10:46），但用户是否确认飞书会话在左侧可见未最终确认
